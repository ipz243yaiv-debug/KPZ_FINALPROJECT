🚀 **Функціонал програми**

- Авторизація та Реєстрація: Повноцінна система акаунтів із хешуванням паролів та збереженням у базу даних SQLite.

- Груповий та Приватні чати: Можливість спілкуватися в загальному каналі або перемикатися на індивідуальні діалоги з користувачами.

- Передача файлів та зображень: Реалізовано механізм серіалізації файлів у byte[] для передачі через мережу. Зображення автоматично відмальовуються в чаті.

- Кастомний UI (GDI+): Повністю самописні графічні елементи: круглі аватарки, повідомлення-бабли (bubbles), сучасний список користувачів та адаптивна верстка.

- Керування профілем: Можливість зміни нікнейму в реальному часі з автоматичним оновленням у всіх підключених клієнтів.

- Локальна історія: Збереження повідомлень у текстові файли для доступу до чату офлайн.

🏛 **Programming Principles**

У проєкті реалізовано наступні принципи програмування:

- *Single Responsibility Principle*: Кожен клас виконує лише одну функцію. UserRepository займається тільки базою, ChatService — логікою WCF, а ChatHistoryPanel — відображенням повідомлень.

- *Dependency Inversion Principle*: Клієнт не створює UI-елементи напряму, а використовує абстракцію IUIFactory, що дозволяє легко змінити стиль інтерфейсу.

- *KISS*: Код написаний максимально простою та зрозумілою структурою без надмірних ускладнень для полегшення підтримки.

- *DRY*: Логіка роботи з мережею та обробка помилок винесені в єдиний клас ChatServerConnector, що уникає дублювання коду в різних формах.

- *Encapsulation*: Всі внутрішні дані користувачів та логіка обробки повідомлень приховані за приватними полями та методами, доступ до яких здійснюється лише через публічні інтерфейси.

Проєкт використовує такі патерни проєктування:

- *Singleton*: Використовується в класі ChatServerConnector. Це гарантує, що клієнт має лише одне стабільне підключення до сервера на всю програму.

🔧 **Refactoring Techniques**

Під час розробки були застосовані такі техніки рефакторингу:

- *Extract Method*: Велика логіка ініціалізації теми у Form1 була винесена в окремий метод ApplyModernTheme.

- *Extract Class*: Логіка роботи з базою даних була повністю винесена з WCF-сервісу в окремий проект, що розділило бізнес-логіку та рівень даних.

- *Move Method*: Обробка вхідних файлів була перенесена ближче до логіки UI, щоб забезпечити коректне відображення в реальному часі.

- *Rename Method*: Методи Connect та Disconnect були перейменовані та перевантажені для підтримки передачі UserId, що зробило їх назви більш змістовними.

- *Replace Magic Number with Symbolic Constant*: Всі розміри баблів, відступи та колірні схеми замінені на іменовані константи та змінні для легкого налаштування візуалу.
